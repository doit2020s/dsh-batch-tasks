# DSH 批量任务工作台

DeepSeek Harness 原生 Cordis 插件。导入 UTF-8 文本，每行一个任务；选择执行 Agent 预设并设置并发上限，每条任务创建独立会话，结束后自动投递下一条。

## 安装

需要已安装的官方 `@deepseek-ai/dsh`、Node.js 22.19 或更新版本，以及可用的模型凭据。

从源码构建安装包：

```powershell
git clone https://github.com/doit2020s/dsh-batch-tasks.git
cd dsh-batch-tasks
npm ci
npm pack
```

在 PowerShell 中执行（把路径换成插件包实际位置）：

```powershell
dsh plugin --profile web add "C:\path\dsh-batch-tasks-0.1.7.tgz"
dsh web
```

若 Web 服务已运行，需要正常退出后重新启动，才能加载新增插件。用 `dsh web` 输出的认证链接打开页面，在 **设置 → 批量任务 → 打开批量任务工作台** 进入。已有会话的顶部也有“批量任务”入口。

开发目录也可直接安装：`dsh plugin --profile web add "C:\path\dsh-batch-tasks"`。修改源码后执行 `npm run build` 并重新启动宿主。

本包按官方 bundle 清单、Cordis 生命周期、客户端模块加载器和原生 slots 实现；批量执行复用官方 SDK JSON-RPC 服务及会话 API，并在发送任务前确认 Agent 预设已挂载。当前版本已在 Windows + DSH Desktop 2.0.13 内置的 Harness 0.1.5-rc.2 中验证。

## 使用

1. 粘贴任务，或导入 UTF-8 TXT。空行忽略，重复行保留，保留原始行号。
2. 设置并发会话数（1～16）、**批次工作根目录**、**执行 Agent 预设**、模型提供方与模型名。根目录由你填写，必须是本机已存在的绝对路径。从会话顶部打开时默认带入当前会话目录，也可以直接修改；从设置页打开时自行填写。Agent 预设默认为 DSH Desktop 当前设置的默认预设，也可在下拉列表中选择其他可用预设；损坏的预设会显示原因且不能选择。模型初值取宿主当前选择。
3. 点击开始。每个批次在根目录下建立 `batch-<批次 UUID>` 文件夹；每条任务按输入顺序使用自己的 `task-00001`、`task-00002` 等子目录。任务的工作目录就是这个子目录，相对路径生成的文件保存在其中，因此不同任务可以使用相同的相对输出文件名。待投递任务的路径已显示，但子目录在真正投递时才创建。
4. 任务状态包括待投递、启动中、执行中、已完成、失败和中断。每个任务使用新的会话 ID，互不继承对话上下文，但使用本批次选定的同一个 Agent 预设。未选择可用预设时不能开始投递。
5. 暂停投递只暂停新任务，已开始的继续执行。可修改并发上限；降低上限不会杀死已有任务，待它们结束后遵循新上限。
6. 任务输入区的“停止投递并关闭会话”在运行或暂停时都可使用：取消所有待投递任务，向本插件创建的 SDK 进程请求正常退出；10 秒未退出则强制结束进程树。执行队列区也提供停止全部、立即强制中断全部或单个任务的操作。
7. 点击任务查看文本结果、错误、会话 ID、Agent 预设和任务目录，可复制目录路径。已完成或失败的任务可以从详情点击“打开会话”。批次信息也显示预设，可导出本批次 JSON；批次停止或结束后可点击“清空列表”移除当前批次记录。清空列表不会删除 DSH 会话日志或任务工作目录。

关闭面板不停止任务。插件会尝试刷新桌面会话列表；批量任务的会话工作目录是各自的子目录，通常显示在左侧“未分组”，不会自动归入根目录对应的工作区。会话对话日志仍由 DSH 保存在共享的 `DSH_HOME` 中，供左侧列表和“打开会话”读取；它不是任务产物，不会复制到任务子目录。退出 DSH 宿主会停止本插件的任务并取消待投递任务。强制结束的是执行进程，会话日志保留，不删除会话，也不会回滚已经完成的文件操作。

## 执行环境与工具插件

首次开始时自动从官方 `sdk` 模板创建独立 `batch-sdk` Profile。后续复用该配置，不会重复覆盖。它与宿主共用 `DSH_HOME` 下的凭据、设置、Agent 预设目录和持久化会话；不复制 Web/桌面 Profile 的插件配置。选择的是 DSH 真正的 Agent 预设，它决定每条会话加载哪些工具和提示词，不能用模型名称代替。预设引用的插件须能在执行 Profile 中加载；无法加载时应报错而不改用其他预设。

自定义预设引用的插件包也必须能由当前 DSH 执行环境的加载器解析。仅安装到 `batch-sdk` Profile 不一定足够，尤其是 Desktop 打包版本；实际挂载失败时批次会暂停，界面显示完整错误，不会改用其它 Agent。

首次批次创建前，可手动初始化：

```powershell
dsh --profile batch-sdk --from-default-profile sdk --dump-config
```

这个插件不会自动提升 DSH 权限。当前面板未实现交互审批或追问转发，需要用户确认的工具可能等待直到超时。无人值守任务应使用已经配置好权限、无需交互的 SDK 工具流程。每个任务的工作目录独立，但工具若使用任务目录以外的绝对路径，仍可能修改外部文件。

若无法自动定位 DSH（例如部分 Electron 桌面打包环境），可为宿主设置 `DSH_BATCH_DSH_BIN` 为官方包 `lib/bin.js` 的绝对路径、`DSH_BATCH_NODE` 为 Node 可执行文件。也可以在 Cordis 插件配置中指定 `dshBin`、`nodePath`、`dshHome`。

## 完成、停止与持久化语义

- “已完成”要求官方 SDK 收到任务、根会话产生 `turn/end` 且原因为 `completed`、执行进程正常退出。仅投递成功不算完成；完成表示本轮正常结束，不保证任务质量达标。
- 每个并发名额由一个独立 SDK 子进程占用，只有确认进程退出后才释放。Windows 强制停止使用目标 PID 的 `taskkill /T /F`，不按进程名称全局结束 Node 或其他 DSH 会话。
- 普通子进程随执行进程树中断；外部远程操作、脱离进程树的后台服务和已完成的副作用不在终止保证内。操作系统拒绝结束进程时保留占用状态，显示错误，不虚报成功。
- 队列位于 `DSH_HOME/batch-tasks/queue.json`，采用原子替换和单宿主锁；完成批次在创建下一批时归档。完整会话由 DSH 保存，面板仅保留每条任务最后 100000 字符文本。旧版本批次可能没有独立的任务目录或 Agent 预设字段；面板会分别标明“旧批次共用工作目录”和“未指定（旧批次）”，不会改变旧会话的实际配置。旧版暂停批次若没有绑定预设，不能继续投递，须停止剩余任务后新建批次。
- 宿主异常退出后，原执行任务标为“服务中断”，不会自动重发；剩余待投递任务恢复为暂停。异常退出不是所有外部副作用都已停止的证明，恢复前应确认相关进程状态。
- 单批最多 10000 条，单条最多 64000 字符，总文本最多 400 万字符；默认单任务超时 30 分钟，可设 1～1440 分钟。
- 插件 API 使用宿主的认证和 Origin/Host 防护，不开另一个无认证端口。任务内容会发送给所选模型，与普通 DSH 任务相同。

## 开发与验证

```powershell
npm ci
npm run build
npm test
npm run test:integration
npm run test:ui
npm pack
```

UI 测试需要本机 Chrome/Edge，或 Playwright Chromium；可通过 `CHROME_PATH` 指定浏览器。测试使用临时 DSH_HOME 和本地模拟模型，不读取生产密钥，不消费真实模型额度。

测试覆盖：100 条任务有界并发与自动补位、暂停继续、调整并发、停止竞态、异常恢复、队列锁、Windows 不响应退出的子进程树强杀；真实官方 SDK 的握手、执行与日志落盘；原生 DSH 页面中的 6 条连续任务、第二批启动、2 个执行进程强制中断、1 条待投递取消及无认证请求拒绝。模型回复由本地测试服务模拟，不代表已验证所有第三方工具或真实业务任务。

源码：`src/index.js` 为 Cordis 宿主入口，`src/client.jsx` 为面板，`src/queue.js` 为调度，`src/worker.js` 为 SDK 传输与终止，`cordis.patch.yml` 为官方 bundle 注入声明。`lib/client.js` 是预编译的官方客户端模块格式，安装包无需本机编译 React。
