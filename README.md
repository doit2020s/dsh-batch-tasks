# DSH 批量任务工作台

DeepSeek Harness 原生 Cordis 插件。导入 UTF-8 文本，每行一个任务；选择执行 Agent 预设，每条任务创建独立会话和工作目录。默认串行执行；设置更大的并发数后，空闲名额自动补位。任务使用独立 SDK 进程，工作台接入 DSH 自身的设置、会话列表和工作区服务。

## 安装

需要已安装的官方 `@deepseek-ai/dsh`、Node.js 22.19 或更新版本，以及可用的模型凭据。

从源码构建安装包：

```powershell
git clone https://github.com/doit2020s/dsh-batch-tasks.git
cd dsh-batch-tasks
npm ci
npm pack
```

在 PowerShell 中执行（把路径换成插件包实际位置）：

```powershell
dsh plugin --profile web add "C:\path\dsh-batch-tasks-<版本号>.tgz"
dsh web
```

若 Web 服务已运行，需要正常退出后重新启动，才能加载新增插件。用 `dsh web` 输出的认证链接打开页面，点击**侧栏底部的“批量任务”**进入；新会话页面也能直接打开，无需先发送消息。侧栏折叠时入口显示为四格图标。也可从 **设置 → 批量任务 → 打开批量任务工作台** 或已有会话顶部进入。DSH Desktop 的 `desktop` Profile 由 Electron 应用管理，普通 Harness CLI 会拒绝直接执行 `dsh plugin --profile desktop add`；请使用该 Desktop 版本提供的插件管理入口或专用终端安装方式。新增或更新插件后正常重启一次应用以加载。加载完成后，日常批量投递通过运行中的宿主登记会话，不需要重启应用。

开发目录也可直接安装：`dsh plugin --profile web add "C:\path\dsh-batch-tasks"`。修改源码后执行 `npm run build` 并重新启动宿主。

本包按官方 bundle 清单、Cordis 生命周期、客户端模块加载器和原生 slots 实现；批量执行复用官方 SDK JSON-RPC 传输与会话 API，并在发送任务前确认选定 Agent 已挂载。实际兼容性验证范围是 Windows + DSH Desktop 2.0.13 内置的 **Harness 0.1.5-rc.2**。较新 Harness 的 Agent 架构有所变化，目前不声明已经完成较新版本的端到端兼容性验证。

## 使用

1. 粘贴任务，或导入 UTF-8 TXT。空行忽略，重复行保留，保留原始行号。可填写**每行前缀**和**每行后缀**；开始执行时每一行会拼接成「前缀 + 本行 + 后缀」。不会自动加空格或换行。前后缀写入 `DSH_HOME/batch-tasks/queue.json`，关掉 DSH 再打开仍在，清空列表也不会丢掉。
2. 设置**并发会话数**（1～16）、**批次工作根目录**、**执行 Agent 预设**、模型提供方与模型名。默认并发为 1（一条接一条）；改大后空闲名额自动补位。根目录由你填写，必须是本机已存在的绝对路径。从会话顶部打开时默认带入当前会话目录，也可以直接修改；从设置页打开时自行填写。Agent 下拉列表直接使用当前宿主的官方注册表，包含系统 Agent 和已注册的用户 Agent；在已验证的运行时中，系统 Agent 包括标准、PTC、极简和创造模式。默认选中宿主当前设置的默认 Agent；损坏的预设会显示原因且不能选择。模型初值取宿主当前选择。插件不修改用户 Agent 预设。
3. 点击开始。投递会话集中登记在填写的 DSH 根工作区；每条任务在根目录下用任务名（原文行）建立自己的文件子目录。非法路径字符会替换，同批次重名会加数字后缀。目录已存在时会复用；需要隔离不同批次时，请选择不同根目录。插件通过官方系统提示和工具 guard 提供任务目录：文件工具使用绝对路径，Shell 工具显式指定目录；隐式根目录调用会被拒绝并提供正确目录的重试说明，插件不改写工具参数或 Agent 身份。工作根目录和并发数会保存，对话标题使用投递的任务名，会话列表收到宿主更新。
4. 任务状态包括待投递、启动中、执行中、已完成、失败和中断。每个任务使用新的会话 ID，互不继承对话上下文，但使用本批次选定的同一个 Agent 预设。未选择可用预设时不能开始投递。
5. 暂停投递只暂停新任务，已开始的继续执行。运行中可调整并发上限；降低上限不会杀死已有任务，待它们结束后遵循新上限。
6. 任务输入区的“停止投递并关闭会话”在运行或暂停时都可使用：取消所有待投递任务，向本插件创建的 SDK 进程请求正常退出；10 秒未退出则强制结束进程树。执行队列区也提供停止全部、立即强制中断全部或单个任务的操作。
7. 点击任务查看文本结果、错误、会话 ID、Agent 预设和任务目录，可复制目录路径。已完成或失败的任务可以从详情点击“打开会话”。批次信息也显示预设，可导出本批次 JSON；批次停止或结束后可点击“清空列表”移除当前批次记录。清空列表不会删除 DSH 会话日志或任务工作目录。

关闭面板不停止任务。原生插件由宿主服务登记根工作区中的独立会话，不直接从另一个进程改写工作区存储，不强制关闭或重启 Desktop。若登记失败，队列会显示错误，便于区分会话执行失败与列表登记失败。会话日志仍由 DSH 保存在共享的 `DSH_HOME` 中，不会复制到任务子目录。退出 DSH 宿主会停止本插件的任务并取消待投递任务。强制结束的是执行进程，会话日志保留，不删除会话，也不会回滚已经完成的文件操作。

## 执行环境与工具插件

首次开始时自动从官方 `sdk` 模板创建独立 `batch-sdk` Profile。后续复用该配置，不会重复覆盖。它与宿主共用 `DSH_HOME` 下的凭据、设置、Agent 预设目录和持久化会话；不复制 Web/桌面 Profile 的插件配置。选择的是 DSH 真正的 Agent 预设，它决定每条会话加载哪些工具和提示词，不能用模型名称代替。预设引用的插件须能在执行 Profile 中加载；无法加载时应报错而不改用其他预设。

所选 Agent 引用的工具插件必须能由当前执行环境正常加载。批量插件不自动复制第三方包到 Harness 或 Desktop 的安装目录，不替用户改写 Agent 配置。实际挂载失败时批次暂停，界面显示错误，不会改用其他 Agent。独立 Profile 的已有配置会保留；缺失时才由官方 CLI 从 SDK 模板初始化。

首次批次创建前，可手动初始化：

```powershell
dsh --profile batch-sdk --from-default-profile sdk --dump-config
```

这个插件不会自动提升 DSH 权限。当前面板未实现交互审批或追问转发，需要用户确认的工具可能等待直到超时。无人值守任务应使用已经配置好权限、无需交互的 SDK 工具流程。每个任务的工作目录独立，但工具若使用任务目录以外的绝对路径，仍可能修改外部文件。

若无法自动定位 DSH（例如部分 Electron 桌面打包环境），可为宿主设置 `DSH_BATCH_DSH_BIN` 为官方包 `lib/bin.js` 的绝对路径、`DSH_BATCH_NODE` 为 Node 可执行文件。也可以在 Cordis 插件配置中指定 `dshBin`、`nodePath`、`dshHome`。

## 可选的外部 CLI

原生插件是默认接入方式。保留的外部界面可用于独立调试：

```powershell
npm run build
npm start
```

安装本包后也可运行 `dsh-batch`。外部界面默认绑定 `http://127.0.0.1:17897/`，`DSH_BATCH_PORT` 可改端口，`DSH_BATCH_NO_BROWSER=1` 可禁用自动打开浏览器。它有自己的本地 HTTP 界面，不使用 DSH 宿主的页面认证，且不会自动取得运行中宿主的工作区注册能力；需要完整会话列表接入时使用原生插件。

原生模式与外部 CLI **不能同时使用同一个 `DSH_HOME` 的批量队列**。队列使用单宿主锁；切换模式前先停止当前任务并退出原来的队列宿主。隔离调试时设置独立的 `DSH_HOME`，使用其自己的凭据与配置。

## 完成、停止与持久化语义

- “已完成”要求官方 SDK 收到任务、根会话 `turn/end` 原因为 `completed`、**已收到的本地 `subagent.started` / 根会话 `subagent` 工具均已结束**、根会话空闲、执行进程正常退出。主 agent 先空闲而子 agent 仍在跑时不得结束任务，也不得投下一条。默认串行投递。仅投递成功不算完成。
- 输入框文本会随设置保存，重新打开工作台时可恢复。只打开或关闭面板不会覆盖已保存的设置，即使首次读取尚未完成就关闭，也会保留原有输入。正常退出宿主会停止执行并取消待投递任务；重新打开面板不会自动重跑。旧版本保留的 `inboxDraft` 仍可回填输入框，开始下一批次时清除该旧缓存。
- 每行前缀、后缀、输入文本、工作根目录和并发设置与队列一起持久化。清空列表保留这些输入设置，只清除插件中的批次和投递记录，不删除 DSH 会话或任务文件；有运行中、待投递任务，或批次仍为运行/暂停时，必须先停止并等待执行进程退出，才能清空。
- 每个并发名额由一个独立 SDK 子进程占用，只有确认进程退出后才释放。Windows 强制停止使用目标 PID 的 `taskkill /T /F`，不按进程名称全局结束 Node 或其他 DSH 会话。
- 普通子进程随执行进程树中断；外部远程操作、脱离进程树的后台服务和已完成的副作用不在终止保证内。操作系统拒绝结束进程时保留占用状态，显示错误，不虚报成功。
- 队列位于 `DSH_HOME/batch-tasks/queue.json`，采用原子替换和单宿主锁；存活宿主的锁不会因运行时间过长被另一个进程抢走。完成批次在创建下一批时归档。完整会话由 DSH 保存，面板仅保留每条任务最后 100000 字符文本。旧版本批次可能没有独立的任务目录或 Agent 预设字段；面板会分别标明“旧批次共用工作目录”和“未指定（旧批次）”，不会改变旧会话的实际配置。旧版暂停批次若没有绑定预设，不能继续投递，须停止剩余任务后新建批次。
- 宿主异常退出后，原执行任务标为“服务中断”，不会自动重发；有剩余待投递任务时批次恢复为暂停，待投递记录与输入文本保留，由用户决定停止或继续。异常退出不是所有外部副作用都已停止的证明，恢复前应确认相关进程状态。
- 单批最多 10000 条，单条最多 64000 字符，总文本最多 400 万字符；界面默认无进展超时 180 分钟，可设 1～1440 分钟，任务硬上限为 12 小时。
- 原生插件 API 使用宿主的认证和 Origin/Host 防护，不另开 API 端口。任务内容发送给所选模型，与普通 DSH 任务相同。

## 开发与验证

```powershell
npm ci
npm run build
npm test
npm run test:integration
npm run test:ui
npm pack
```

UI 测试需要本机 Chrome/Edge，或 Playwright Chromium；可通过 `CHROME_PATH` 指定浏览器。测试使用临时 DSH_HOME 和本地模拟模型，不读取生产密钥，不消费真实模型额度。

测试覆盖队列并发、暂停继续、停止竞态、清空约束、异常恢复、系统 Agent 列表、Profile 配置保留、工作区会话登记及执行进程终止。SDK 与界面集成测试使用简单逻辑任务、临时目录和本地模拟模型验证传输、工具调用、日志落盘和宿主列表更新。模型回复由本地测试服务模拟，不代表已验证所有第三方工具、所有 Harness 版本或真实业务任务。无需检查或修改生产用户 Agent 配置即可运行这些测试。

源码：`src/index.js` 为 Cordis 宿主入口，`src/core.js` 为共享批量服务，`src/client.jsx` 为面板，`src/queue.js` 为调度，`src/worker.js` 为 SDK 传输与终止，`src/desktop-bridge.js` 和 `src/workspace-attach.js` 接入官方工作区服务，`cordis.patch.yml` 为官方 bundle 注入声明。`lib/client.js` 是预编译的官方客户端模块格式，安装包无需本机编译 React。
